# 需求文档

- 更新日期：2026-11-02
- 状态：第 3 版。需求已全部确认，下一步设计数据表。

## 1. 概要

日语课程管理用的 LINE MINI App。学生和老师在 LINE 中打开，可以：

- 查看课程进度：已上多少节、还剩多少课时、下一节课的时间。
- 用日历查看课程表。
- 在每节课下面留言沟通，例如课程内容、教材截图、请假。

本程序**不涉及交易**。课时由学生申请、老师确认。

使用者很少（老师 1～几人，学生几人），老师年纪较大，所以界面要**字大、步骤少、按钮少**。

## 2. 角色

| 角色   | 怎么成为                                 | 能看到的内容                                                                     |
| ------ | ---------------------------------------- | -------------------------------------------------------------------------------- |
| 学生   | 首次进入时自己选择                       | 自己关联的老师，以及和这些老师的课程、留言                                       |
| 老师   | 首次进入时自己选择                       | 自己关联的学生，以及和这些学生的课程、留言                                       |
| 管理员 | 不能自己选择，由开发者直接在数据库中设置 | 所有老师、所有学生的内容，只能查看（不另做管理页面，使用和老师、学生相同的页面） |

- 老师和学生是多对多：一个学生可以有多位老师，一位老师可以有多个学生。
- 身份选定后用户自己不能修改，选错时由管理员修改。
- 管理员是附加在老师或学生身份之上的权限，例如你本人可以既是学生又是管理员。

## 3. 多语言与时区

- 界面支持**日语**和**中文**。初始语言跟随手机的语言设置，用户可以在页面上切换，切换后记住选择。这部分已实现。
- 用户自己输入的内容（名字、自我介绍、留言）原样显示，不做翻译。
- 日期、星期的写法按界面语言显示，例如日语「11月5日(水) 13:00」、中文「11月5日 周三 13:00」。
- 时间按查看者手机的时区显示。排课画面底部显示当前时区，例如「当前时区：Asia/Tokyo (GMT+9:00)」。

## 4. 首次使用流程

1. 在 LINE 中打开 MINI App，自动登录，取得 LINE 名字和头像。这一步已实现。
2. **选择身份**：老师 / 学生。
3. **填写基本信息**：
   - 名字：必填，默认填入 LINE 名字，可以修改。
   - 自我介绍：选填。
   - 头像：使用 LINE 头像，不需要上传。
4. 进入 dashboard。

通过邀请消息第一次进入的人（见第 9 节）同样要完成第 2、3 步，只是身份会预先选好为邀请人的相反身份。

基本信息以后可以在设置中修改。

## 5. Dashboard

所有功能都在一个 dashboard 内完成。首页上方是「下一节课」卡片，下方分两个标签：

| 标签                   | 内容                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **课程表**（默认显示） | 月历。有课的日期带标记，点某一天会在月历下方列出当天的课（时间、对方的名字、状态），点某节课进入课程详情。默认选中今天。 |
| **老师 / 学生**        | 学生看到「老师」列表，老师看到「学生」列表。每人显示头像、名字、下一节课时间、剩余课时，点进去是详情页。                 |

### 5.1 学生看到的内容

- **老师详情**：
  - 基本信息：头像、名字、自我介绍。
  - 统计：已上课程数、剩余课时、下一节课时间。
  - 课程列表：分为「即将上的课」和「已上的课」。
  - 「申请增加课时」按钮，以及过去的申请记录（见第 6 节）。
- 「老师」标签中有「邀请老师」按钮（见第 9 节）。

### 5.2 老师看到的内容

- **学生详情**：
  - 基本信息：头像、名字、自我介绍。
  - 统计：总课时、已上课程数、剩余课时、下一节课时间。
  - 课程列表：与学生看到的相同。
  - **「安排课程」按钮**（见第 7 节）。
  - 待处理的课时申请，带「确认」「拒绝」按钮。
- 有待处理的课时申请时，首页显示提示，例如「有 1 个课时申请待处理」。
- 「学生」标签中有「邀请学生」按钮。

### 5.3 管理员看到的内容

- 课程表：显示所有人的课。
- 列表：显示所有师生关系（老师 × 学生）。点进去后，看到的内容与学生、老师看到的详情相同。
- 只能查看，不能留言、排课或处理申请。

### 5.4 课程详情（老师、学生共用）

- 显示上课日期时间（例如 11月5日(水) 13:00～13:50）和状态（已安排 / 已上 / 已取消）。
- 下面是这节课的留言板（见第 8 节）。
- 学生可以使用「请假」按钮，老师可以使用「取消这节课」「改时间」按钮。这些按钮只在上课开始之前显示。

## 6. 课时（申请制）

1. **学生申请**：在老师详情中点「申请增加课时」，输入要增加的课时数（例如 10）和备注（选填），提交。
2. **老师处理**：在学生详情中看到申请，点「确认」或「拒绝」。
   - 确认后，总课时增加。
   - 拒绝时可以填写理由（选填）。
3. **学生查看结果**：在申请记录中看到「待处理 / 已确认 / 已拒绝」。

补充规则：

- 同一对师生之间，同时只能有 1 个待处理的申请。
- 申请处理之前，学生可以撤回。
- 刚建立关联时课时为 0。

课时的计算方法：

| 项目     | 计算方法                                                    |
| -------- | ----------------------------------------------------------- |
| 1 节课   | 1 课时，50 分钟                                             |
| 总课时   | 所有已确认申请的课时之和                                    |
| 已上     | 上课时间已过、且没有取消的课                                |
| 剩余课时 | 总课时 − 已排好的课（包括已上的和还没上的，不包括已取消的） |

课排好时就从剩余课时中扣除，取消后返还（见第 7 节）。

## 7. 排课（老师操作）

老师在学生详情中点「安排课程」，打开排课画面，参考你给的截图的形式。

### 7.1 时段

- 每节课 50 分钟，整点开始，例如 13:00～13:50、14:00～14:50。
- 画面中可选的开始时间为 8:00～21:00，最后一节是 21:00～21:50。

### 7.2 排课画面

画面上方有两个标签：

**每周课程**：每周在相同时间重复。

- 7 列（周一～周日）× 时段的格子。
- 点格子选中，再点取消选中。可以选多个，例如每周一、周四的 13:00。
- 点「保存」后，按 7.3 的规则自动排课。

**单次课程**：任选某一天的时间。

- 一次显示一周的日期 × 时段，标题例如「2026年11月2日～8日」。用左右箭头切换上一周、下一周。
- 点格子添加一节课。

格子的状态：

| 状态                 | 显示                                                           |
| -------------------- | -------------------------------------------------------------- |
| 可选                 | 白底带边框                                                     |
| 已选（这个学生的课） | 高亮颜色                                                       |
| 不可选               | 灰色。包括已过去的时间，以及这位老师在这个时段已有其他学生的课 |

画面底部显示当前时区。

### 7.3 每周课程按月排课

**每月最后一天，系统按每周课程的规则，自动排好下个月一整个月的课，并从剩余课时中扣除。**

例：每周一、周四各 1 节，下个月共 8 节，剩余 30 课时。月末自动排好下个月的 8 节，剩余课时变为 22。

- 「月」按日本时间计算。
- 剩余课时不够时，按日期先后排到课时用完为止。
  - 课时用完后，学生的老师详情显示「课时已用完，请申请增加课时」。
  - 老师确认新的课时申请后，自动补排本月剩下的、因课时不足没排上的课。
- 老师第一次设置每周课程时，立即排好本月剩下的课，不等到月末。
- 请假或取消的课返还 1 课时，不自动补课。需要补课时，老师用单次课程添加。
- 单次课程添加时就扣 1 课时。

### 7.4 修改

- 老师可以随时修改或停止每周课程。
  - 修改时，已排好但还没上的课按新规则重新排，并相应扣除或返还课时。
  - 停止时，已排好但还没上的课全部取消，并返还课时。
  - 已上的课不受影响。
- 某一节课可以单独取消或改时间。改时间时打开单次课程画面，选新的时段。
- 剩余课时为 0 时，不能再添加单次课程，画面提示需要学生先申请课时。
- 同一位老师在同一时段只能有 1 节课。

## 8. 留言板（每节课一个）

- 能看到并发言的人：这节课的老师和学生。管理员只能查看。
- 留言按时间顺序显示，显示发言人的头像、名字和发言时间。
- 只能删除自己的留言，不能编辑。

### 8.1 图片

用于老师课后发教材截图。

- 1 条留言可以带文字和最多 9 张图片，也可以只发图片。
- 上传前在手机上自动压缩，长边最大 2048 像素，保证教材上的文字看得清。
- 点图片可以放大查看，支持双指缩放。
- 图片不公开，只有这节课的老师、学生和管理员能看到。
- 图片保存在 Cloudflare R2（对象存储）。免费额度为每月 10 GB 存储，读取流量免费。按压缩后每张约 0.5 MB 计算，大约可以存 2 万张，本项目用不完。
- **需要你操作**：在 Cloudflare 控制台开通 R2，开通时可能要求登记信用卡或 PayPal，只要不超过免费额度就不会扣费。开通后，存储桶（bucket）由我用命令创建。

### 8.2 请假与取消

- **请假**：学生在课程详情中点「请假」，可以填写理由（选填）。之后：
  - 留言板中自动出现一条「请假」留言。
  - 这节课变为「已取消」，不扣课时。
- **取消这节课**：老师取消课程时，同样在留言板中自动留下记录。

## 9. 师生关联（通过 LINE 好友邀请）

### 9.1 实现方式

使用 LIFF 的 `liff.shareTargetPicker()`。

- 调用后打开 LINE 自带的好友选择画面，以用户本人的名义把一张带按钮的邀请卡片发给选中的好友。
- 控制台中已经开启。

| 限制                                                                                                   | 应对方法                                                                                   |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 程序无法知道用户选了哪位好友，只能得知「发送成功」。                                                   | 在卡片按钮的链接中附带**邀请码**。对方点按钮打开 MINI App 时，后端凭邀请码判断是谁邀请的。 |
| 卡片发出后可能被转发给别人。                                                                           | 邀请码只能使用 1 次，有效期 7 天。                                                         |
| 对方关闭了「允许外部应用访问」等设置时，不会出现在好友列表中；在外部浏览器中可能无法打开好友选择画面。 | 同时提供「复制邀请链接」，可以手动贴到 LINE 聊天中。                                       |
| 官方文档没有写明未认证的 MINI App 是否有限制。                                                         | 开发时先用手机实际确认。                                                                   |

### 9.2 邀请流程

1. A 在「老师 / 学生」标签中点「邀请学生」或「邀请老师」。后端生成邀请码，记录邀请人和邀请人的身份。
2. 打开 LINE 好友选择画面，A 选择 1 位好友 B（每次邀请只发给 1 人）。
3. B 收到 A 发来的日语、中文双语卡片，例如「○○ 先生があなたを招待しました / ○○ 老师邀请了你」，卡片上有「查看邀请」按钮。
4. B 点按钮，打开 MINI App 的邀请确认页：
   - B 还没注册时，先完成身份选择和基本信息（身份预选为与 A 相反的身份）。
   - 页面显示 A 的头像、名字和自我介绍，B 点「接受」即建立关联。
5. 以下情况显示提示，不建立关联：
   - B 与 A 身份相同。老师之间、学生之间不能关联。
   - 两人已经关联。
   - 邀请码已过期或已使用。
   - B 打开的是自己发出的邀请。

第一版不做解除关联的功能，需要时由管理员处理。

## 10. 不在第一版范围内

- **自动推送通知**，例如上课前提醒、收到新留言、收到课时申请。
  - 需要另外建 LINE 官方账号，并且用户要加它为好友。
  - MINI App 自带的「服务消息」只有通过审核的认证版本才能使用。
  - 第一版不做任何通知。需要时，使用者在 LINE 上直接联系对方。老师打开 dashboard 时，可以看到待处理的课时申请提示。
- 收费、支付。
- 解除师生关联。

## 11. 主要数据（概念）

具体的表和字段见 [数据库设计](database.md)。

| 数据         | 说明                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| 用户         | LINE 账号、名字、头像、自我介绍、身份（老师 / 学生）、是否管理员                                      |
| 师生关系     | 哪位老师和哪个学生关联、关联时间                                                                      |
| 邀请         | 邀请码、邀请人、有效期、是否已使用、被谁接受                                                          |
| 课时申请     | 属于哪个师生关系、申请课时数、备注、状态（待处理 / 已确认 / 已拒绝 / 已撤回）、处理时间、拒绝理由     |
| 每周课程规则 | 属于哪个师生关系、星期几、开始时间、开始日期、是否停止                                                |
| 课程         | 属于哪个师生关系、开始时间（50 分钟固定）、来源（每周规则 / 单次）、状态（已安排 / 已取消）、取消理由 |
| 留言         | 属于哪节课、发言人、文字、类型（普通 / 请假 / 取消）、发言时间                                        |
| 留言图片     | 属于哪条留言、在 R2 中的保存位置、宽高、顺序                                                          |
