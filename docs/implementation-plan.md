## 1. 总体方针

1. **分 10 个阶段（0～9）按顺序进行。** 每个阶段完成后，经你同意再提交推送，自动部署到线上。你用手机确认没问题后，再进入下一阶段。
2. **风险最大的部分先验证。** 未认证 MINI App 能否使用 LINE 好友选择画面、点开邀请卡片能否进入指定页面，都放在阶段 2 的开头，先用最小的代码在手机上确认。
3. **在全部完成之前，只有你在用。** 线上没有测试环境，但老师等到阶段 9 完成后再邀请。期间的测试数据在阶段 9 清理。
4. **每个阶段内的顺序：**
   1. 表定义
   2. repository（数据库读写）
   3. service（业务逻辑）
   4. 路由（接口）
   5. 后端测试
   6. 前端调用接口的 hooks
   7. 页面
   8. 中日文案
   9. 本地确认（LIFF Mock，可以切换多个模拟用户）
   10. 提交推送，手机确认
5. **沿用现有写法**，见 README「如何扩展」：
   - routes / services / repositories 分层。
   - 参数的 Zod schema 放在 `shared/`，前后端共用。
   - 出错时抛出 `ApiError` 并带错误码，前端按错误码显示对应语言的提示。
   - 页面文字写在 `locales/zh.ts`、`ja.ts`。
   - 注释和提交信息使用中文。
6. **推送前在本地执行** `pnpm typecheck`、`pnpm lint`、`pnpm test`，全部通过才推送。每个阶段提交 1～3 次。

### 3.2 当前用户与权限

**识别当前用户：**

- 沿用 `requireAuth`：校验 LINE ID token，取得 LINE 用户。
- 新增 `loadCurrentUser`：按 LINE userId 从 `users` 表取得本系统的用户，后续用 `c.get("currentUser")` 使用。
  - 用户记录由 `GET /api/me` 创建。前端启动时一定先调用这个接口。
- 新增 `requireRegistered`：`role` 或 `name` 为空时返回 403，错误码 `NOT_REGISTERED`。除了首次设置和邀请确认，其他接口都需要。

**权限规则：**

| 操作                             | 学生            | 老师            | 管理员     |
| -------------------------------- | --------------- | --------------- | ---------- |
| 查看师生关系、课程、留言、图片   | 自己参与的      | 自己参与的      | 全部       |
| 发出邀请、接受邀请               | ✓               | ✓               | 按本人身份 |
| 申请课时、撤回申请               | ✓（自己的关系） |                 |            |
| 确认、拒绝课时申请               |                 | ✓（自己的关系） |            |
| 每周课程、单次课程、取消、改时间 |                 | ✓（自己的关系） |            |
| 请假                             | ✓（自己的课）   |                 |            |
| 留言、上传图片                   | ✓（自己的课）   | ✓（自己的课）   |            |
| 删除留言                         | 自己发的        | 自己发的        |            |

- 管理员权限只扩大「能看的范围」。管理员本人作为学生或老师参与的关系，照常可以操作。
- 访问自己看不到的师生关系或课程时，返回 404 而不是 403，不透露对象是否存在。
- 判断集中写在 `server/lib/access.ts`，路由和 service 都用这里的函数，不在各处各写一遍。

### 3.3 错误码

在 `shared/types/api.ts` 中追加以下错误码，并在中日文案中写好对应的提示：

| 错误码                    | 状态码 | 场景                                                   |
| ------------------------- | ------ | ------------------------------------------------------ |
| `NOT_REGISTERED`          | 403    | 未完成首次设置                                         |
| `ALREADY_REGISTERED`      | 409    | 已完成首次设置，又提交了一次                           |
| `INVITATION_EXPIRED`      | 409    | 邀请已过期                                             |
| `INVITATION_USED`         | 409    | 邀请已被使用                                           |
| `INVITATION_SELF`         | 409    | 打开的是自己发出的邀请                                 |
| `INVITATION_SAME_ROLE`    | 409    | 老师之间、学生之间不能关联                             |
| `ALREADY_LINKED`          | 409    | 两人已经关联                                           |
| `CREDIT_REQUEST_PENDING`  | 409    | 已有待处理的课时申请                                   |
| `REQUEST_ALREADY_DECIDED` | 409    | 申请已被处理，例如老师同时在两台设备上点了确认         |
| `INSUFFICIENT_CREDITS`    | 409    | 剩余课时不足                                           |
| `SLOT_UNAVAILABLE`        | 409    | 这个时段不能选：已过去、超出范围、老师或学生已有别的课 |
| `LESSON_ALREADY_STARTED`  | 409    | 课已开始，不能再请假、取消或改时间                     |

### 3.4 时间处理

**保存**：一律用 UTC 毫秒，这是现有约定。

**排课计算用日本时间**：写在 `shared/lib/jst.ts`。

- 日本固定为 UTC+9，没有夏令时，不需要时区库，用固定的 9 小时换算即可。
- 主要函数如下，全部是纯函数，有单元测试：

| 函数                                               | 作用                                                      |
| -------------------------------------------------- | --------------------------------------------------------- |
| `toJstParts(date)`                                 | 转为日本时间的年、月、日、时、星期（1 = 周一 … 7 = 周日） |
| `fromJst(year, month, day, hour)`                  | 日本时间的某天某点，转为 Date                             |
| `endOfJstMonth(date)`、`isLastDayOfJstMonth(date)` | 月底的计算                                                |
| `scheduleHorizon(now)`                             | 排课范围：平时到本月底，每月最后一天到下个月底            |
| `weeklyOccurrences(rules, from, to)`               | 每周规则在一段时间内对应的所有开始时间                    |

**显示**：写在 `web/src/lib/format.ts`。

- 用浏览器自带的 `Intl.DateTimeFormat`，按界面语言（`ja-JP` / `zh-CN`）和手机的时区显示。
- 例如日语「11月5日(水) 13:00～13:50」、中文「11月5日 周三 13:00～13:50」。

**排课画面固定使用日本时间**：

- 每周规则是按日本时间定义的，所以排课画面固定显示日本时间，底部标明「日本时间 Asia/Tokyo (GMT+9:00)」。
- 课程表、列表等其他画面按手机的时区显示。
- 老师在日本，所以两者相同。如果你在中国打开，课程表会按中国时间显示。

**可测试性**：用到「现在时间」的 service 函数，都以参数 `now` 传入。路由传入当前时间，测试传入固定的时间。

### 3.6 对数据库设计的 3 处小调整

[数据库设计](database.md) 已同步修改。

| 调整                                                                      | 理由                                                                                                                                             |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `lessons` 新增 `rescheduled_to_id`（改到的那节新课）                      | 留言板要显示「已改到 ○月○日 ○:00」。这句话要按查看者的界面语言显示，不能把某一种语言的文字存进数据库，所以需要记下新课是哪一节，由前端生成文字。 |
| 留言类型新增 `reschedule`（老师改时间）                                   | 与「取消」区分，前端才能显示不同的文字。                                                                                                         |
| `lessons` 中，同一师生关系、同一开始时间、状态为 `scheduled` 的课设为唯一 | 定时任务和老师的操作同时执行时，可能把同一时段排两次。由数据库保证不会重复。                                                                     |

### 3.8 前端的共通做法

- **新增 shadcn 组件**：avatar、badge、tabs、dialog、alert-dialog、input、textarea、label、calendar（月历）、skeleton（加载中）、sonner（操作成功的提示）。
- **新增依赖**：

  - 图片放大用的 yet-another-react-lightbox。
  - 版本在安装时确认，选发布两周以上的稳定版本。
- **数据获取**用 TanStack Query：
  - 操作成功后，让相关的数据重新加载。例如确认课时申请后，重新加载关系详情、列表和课程表。
  - 留言板打开期间每 30 秒刷新一次，其他页面在打开时刷新。
- **危险操作**（取消课程、请假、删除留言、拒绝申请）先弹出确认对话框，写清楚会发生什么。
- **加载中**显示占位框，**出错**显示现有的 `QueryError`（按错误码显示中日提示和重试按钮）。

**本地开发切换模拟用户**（只在 LIFF Mock 模式下显示）：

- 选择保存在 localStorage，请求时作为 `X-Mock-User-Id` 发给后端。
- 这样不用手机，也能在本地测试老师和学生之间的完整流程。

## 4. 各阶段的详细内容

### 阶段 0：基础整理

**后端**

1. **重建数据库**
   - 按 [数据库设计](database.md) 写好全部 8 张表的 schema，包括第 3.6 节的调整。

### 阶段 8：图片留言

**配置**

- `wrangler.jsonc` 中添加 R2 绑定（`IMAGES` → `lesson-schedule-images`）。
- 执行 `pnpm cf-typegen`，更新类型定义。
- 本地开发和测试使用模拟的 R2，不会连到线上。

**后端**

- `POST /api/lessons/:id/images`：
  - 请求体就是图片本身，不用 multipart 表单。
  - 参数：`width`、`height`。
  - 只接受 `image/jpeg`、`image/png`、`image/webp`，最大 5 MB。
  - 文件**直接流式写入 R2**，路径为 `lessons/<课程 id>/<随机 ID>.jpg`，并记下上传人。
  - 返回 `{ key }`。
  - 不用 multipart 的原因：Workers 免费计划每个请求只有 10 毫秒 CPU 时间。一次解析多张图片的表单可能超时，而流式写入几乎不占 CPU。
- 发留言时附带图片：`images: [{ key, width, height, contentType, sizeBytes }]`，最多 9 张。
  - 后端确认每个路径都属于这节课、R2 中存在、上传人是自己。
  - 然后用 batch 写入留言和图片记录。
- `GET /api/images/:id`：
  - 确认查看者有权限后，从 R2 读出返回。
  - 响应头为 `Cache-Control: private, max-age=31536000, immutable`。路径不会变，可以长期缓存。
- 删除留言：数据库中删除成功后，再删除 R2 中的文件。
- 每天的定时任务顺便清理上传了但没发出去的图片：上传超过 24 小时、但不在数据库中的文件。

**前端**

- `lib/image-compress.ts`：
  - 读取照片时自动按拍摄方向转正。
  - 长边缩小到 2048 像素以内，转为 JPEG（质量 0.85）。
- 输入框旁有「照片」按钮，可以一次选多张：

  - 图片需要登录才能获取，不能直接用 `<img src>`。所以前端带上登录凭证请求，转为页面内的临时地址再显示，并缓存起来。
- 点图片全屏查看，可以双指缩放、左右滑动切换。

**测试**

- 发留言时附带别的课的图片路径，被拒绝。
- 获取图片的权限。
- 删除留言后，R2 中的文件也被删除。

## 5. 关键处理的详细设计

### 5.1 统计的计算

对一组师生关系，用 4 个按关系分组的查询算出所有统计，不需要逐个关系查询：

| 项目       | 查询                                                                          |
| ---------- | ----------------------------------------------------------------------------- |
| 总课时     | `credit_requests` 中 `status = 'approved'` 的 `amount` 之和                   |
| 已排好的课 | `lessons` 中 `status = 'scheduled'` 的节数                                    |
| 已上       | 上一项中「开始时间 + 时长 ≤ 现在」的节数                                      |
| 下一节课   | `status = 'scheduled'` 且「开始时间 + 时长 > 现在」的课中，开始时间最早的一节 |

剩余课时 = 总课时 − 已排好的课。

### 5.2 补齐排课

```
fillRelation(关系, now):
  范围结束 = scheduleHorizon(now)        # 日本时间：平时为本月底，每月最后一天为下个月底
  规则 = 这个关系的每周规则
  如果没有规则：结束
  剩余 = 总课时 − 已排好的课
  如果剩余 ≤ 0：结束

  候选 = 规则在 (now, 范围结束] 之间的所有开始时间，按时间升序
  已有 = 这个关系在这段时间内所有课的开始时间（包括已取消的课）
  老师忙 = 老师在其他关系中、这段时间内已安排的课的开始时间
  学生忙 = 学生在其他关系中、这段时间内已安排的课的开始时间

  新课 = []
  对每个候选时间 t：
    如果剩余 = 0：停止
    如果 t 在「已有」「老师忙」「学生忙」中：跳过
    新课.加入({ 关系, 规则 id, 开始时间 t, 时长 50 })
    剩余 −= 1

  一次写入全部新课（遇到唯一索引冲突的跳过）

fillAll(now):
  对每个有每周规则的关系：fillRelation(关系, now)
```

- 已取消的课仍在「已有」中，所以请假、取消过的时段不会被重新排上。
- 每天日本时间 0:00 执行。月末那天就会排好下个月。某天执行失败，第二天也会补上。

### 5.3 保存每周课程（只处理变化的部分）

```
saveWeeklySchedules(关系, 新时段列表, now):
  校验：时段在 8～21 点之间、没有重复、不与老师其他学生的规则冲突
  保留 = 现有规则 ∩ 新时段
  去掉 = 现有规则 − 新时段
  新增 = 新时段 − 现有规则

  对每条「去掉」的规则：
    将来的课 = 这条规则生成的、开始时间 > now、状态为 scheduled 的课
    其中有留言的 → 改为已取消，并在留言板写入取消记录
    其中没有留言的 → 删除
    删除这条规则
  写入「新增」的规则
  fillRelation(关系, now)
```

只处理有变化的时段。如果每次都整体删除再重建，没变化的时段上已有留言的课会被取消，并且不会再排回来。

### 5.4 接受邀请（防止同时操作）

D1 不支持跨多次请求的事务，但 `batch` 中的多条语句在同一事务中执行。

- 第 1 条：`accepted_by_id` 为空时，才把它设为自己。
- 第 2 条：「该邀请的 `accepted_by_id` 是自己」时，才插入师生关系。

如果两个人同时接受，只有先执行的那个人的第 1 条会成功，另一个人的第 2 条什么也不插入，后端返回 `INVITATION_USED`。师生关系表的唯一索引是最后一道保障。

### 5.5 图片的上传与显示

```
选择图片 → 手机上压缩（长边 2048、JPEG）
  → 逐张 POST /api/lessons/:id/images（流式写入 R2）→ 得到路径
  → POST /api/lessons/:id/messages（文字 + 图片路径）
  → 后端确认路径属于这节课、文件存在、上传人是自己 → 写入留言和图片记录

显示：GET /api/images/:id（带登录凭证）→ 检查权限 → 从 R2 读出
  → 前端转为临时地址显示 → 点击后全屏查看，可以缩放
```

## 7. 部署与运维

### 7.1 阶段 0 的数据库重置步骤

执行前我会再向你确认。顺序很重要：

1. 删除线上的旧表：

   ```bash
   pnpm wrangler d1 execute DB --remote --command "DROP TABLE IF EXISTS users; DROP TABLE IF EXISTS d1_migrations;"
   ```

   `d1_migrations` 是记录「哪些迁移已执行」的表。删掉后，新的 `0000_init` 会被当作没执行过。
2. 推送代码。部署时会自动执行 `0000_init`，建好全部新表。
3. 如果先推送、后删表，部署时的迁移会因为 `users` 表已存在而失败。这种情况下线上会继续运行旧版本，不会坏掉，删表后重新部署即可。
4. 万一需要恢复，可以用 D1 的 Time Travel 回到删除前的时间点。

## 8. 风险与对策

| 风险                                   | 对策                                                                                   |
| -------------------------------------- | -------------------------------------------------------------------------------------- |
| 未认证的 MINI App 不能使用好友选择画面 | 阶段 2 先在手机上验证；不行就只提供「复制邀请链接」                                    |

| D1 不支持跨请求的事务                  | 需要同时写入多张表时用 batch；有先后依赖的操作用「条件更新」，并在失败时恢复原状       |
